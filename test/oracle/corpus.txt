#
# Differential-test corpus for `make test-expr-oracle`. Each case is evaluated
# by BOTH sqi's Go evaluator and the OpenJD reference implementation, and the
# two results are compared.
#
# Format: one case per line, a TARGET TYPE and an EXPRESSION separated by a
# single TAB. Blank lines and lines starting with "#" are ignored. A tab is the
# separator because every other candidate appears inside real cases: spaces are
# everywhere, and "|" is a union in the target type ("int | string").
#
# SCOPE: expressions that sub-projects A, B1, B2, B3, C1, C2 and C3 actually
# implement — scalar operators, the coercion matrix, comparison chains,
# conditionals, and/or, list literals and their type inference, list
# operators, subscripts, slices, list comprehensions, C1's general,
# validation, math and list functions, C2's 31 string functions, and C3's
# regular-expression and repr_* families. The path family is sub-project C4
# and is not here yet.
#
# TARGET TYPES MUST BE UNIONS FOR ANY CASE CONTAINING A CALL, A SUBSCRIPT OR A
# SLICE, and this is not a style preference. The reference implementation
# applies the supplied target_type to a construct's OPERANDS as well as to its
# result — reported upstream as openjd-rs#291, and observed here on call
# arguments, subscript receivers and indices, slice bounds, and the operand
# and/or discards. So "floor(3.7)" with the target "int" fails there, because
# the target lands on the 3.7. Give the target a member for every operand and
# the pushdown becomes harmless:
#
#   floor(3.7)               int | float
#   sum([1,2,3])             int | list[int]
#   range(5)                 list[int] | int
#   'hello'[1:3]             string | int | nulltype
#
# A case written with the obvious single target produces a divergence that
# looks real and is not. If you add a case and it diverges, check the target
# before reaching for baseline.txt.
#
# A handful of cases are in deliberately and are expected to diverge. They earn
# their place by DOCUMENTING a gap or a disagreement rather than leaving it
# implicit, and each is listed in baseline.txt with the reason. Do not delete a
# case to make the target green.

# The EMPTY list on either side of an ordering operator. Section 1.2.5 says the
# shorter list is less when all compared elements are equal, and section 1.2.6
# rule 6 makes list[nulltype] convertible to list[T] for any T — so both orders
# must answer, and sqi's did not: "[] < [1]" was a type error while "[1] < []"
# was false, because the empty literal PINNED the shared element-type variable
# to nulltype when it came first. The reference agrees with the fixed behaviour
# on every line here, including the last, where the empty list is nested one
# level deeper than the other operand and there is no conversion at all.
#

# missed: the nested case was pinned in one direction only ("[[]] < [[1]]"), and
